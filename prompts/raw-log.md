P06 이후 기능인 세부 복구 UI나 후순위 기능은 아직 구현하지 않는다.

## 1. 상세 화면(F5)

현재 목록 카드 제목의 링크:

`#/item/{id}`

를 실제 상세 화면으로 연결한다.

예:
`#/item/dept-001`

상세 화면에는 최소한 다음을 표시한다.

- `검색 결과로 돌아가기`
- 출처 배지
- 게시일
- 게시 부서
- 게시물 제목
- 본문
- 첨부 목록
- 샘플 데이터 안내

첨부 파일은 실제 다운로드 링크를 만들지 않는다.

예:
`졸업요건표.pdf · 샘플 · 다운로드 불가`

원문 보기 기능도 실제 URL로 연결하지 않는다.

필요하다면 비활성 버튼이나 안내 문구로:

`실제 원문과 연결되지 않은 샘플입니다.`

라고 표시한다.

## 2. 상세 화면 접근성

CLAUDE.md의 F9 기준을 유지한다.

특히:

- 상세 화면의 제목은 적절한 heading 구조를 사용한다.
- 목록 → 상세 화면으로 이동하면 상세 화면의 주 제목으로 포커스를 이동한다.
- `검색 결과로 돌아가기`는 키보드로 사용할 수 있어야 한다.
- 첨부 파일이 실제로 다운로드되는 것처럼 오인하게 만들지 않는다.
- 출처는 색만이 아니라 텍스트 배지로 표시한다.
- 샘플 데이터 배너를 모든 화면에서 유지한다.

## 3. 탐색 상태를 URL 해시에 저장(F6)

현재 목록 상태를 URL에 저장한다.

저장 대상:

- 검색어
- 선택한 출처
- 기간
- 페이지 번호

예시 형태:

`#/?q=졸업요건&src=dept,haksa&period=1y&page=1`

정확한 파라미터 이름은 기존 구조와 충돌하지 않는 범위에서 정해도 된다.

규칙:

- 아무 조건이 없는 기본 화면은 가능한 한 단순한 `#/` 상태를 유지한다.
- 검색어를 입력하면 URL에 반영한다.
- 출처를 선택/해제하면 URL에 반영한다.
- 기간을 바꾸면 URL에 반영한다.
- 페이지를 바꾸면 URL에 반영한다.
- 조건 변경으로 page가 1로 초기화되면 URL도 page 1 상태를 반영한다.
- 새로고침해도 같은 검색·필터·페이지 상태가 복원되어야 한다.
- URL을 직접 입력해도 해당 상태가 재현되어야 한다.

## 4. 상세 화면으로 이동할 때 목록 상태 유지

예:

`#/?q=졸업요건&src=dept&period=1y&page=1`

상태에서 `dept-001`을 열어도 목록으로 돌아갈 때 위 조건이 유지되어야 한다.

구현 방식은 적절히 선택하되, 상세 화면에서 `검색 결과로 돌아가기`를 누르면 이전 탐색 상태로 돌아갈 수 있어야 한다.

브라우저의 뒤로가기에서도 같은 상태가 복원되어야 한다.

현재 MVP에서는 다음까지만 필수다.

- 검색어 유지
- 출처 유지
- 기간 유지
- 페이지 유지

스크롤 위치와 클릭했던 카드의 포커스 복원은 후순위이므로 아직 구현하지 않는다.

재학생이 필요한 학교 정보의 정확한 제목이나 위치를 몰라도 여러 정보 출처의 샘플 데이터를 한곳에서 탐색할 수 있도록 만든 HCI 웹 프로토타입

### 중요 고지
- 모든 데이터는 HCI 과제용 샘플
- 실제 학교 시스템과 연결되지 않음
- 실제 공지나 공식 서비스가 아님

### 프로젝트 배경
다음 세 수준을 구분해서 짧게 설명한다.

- [관찰] P01이 학사공지 → 일반공지 → 다시 학사공지로 이동하며 정보를 찾은 실제 관찰
- [해석] 게시판 위치를 확신하지 못하면 탐색이 반복되고, 경로가 막히면 처음 화면까지 돌아가는 문제가 있음
- [가설] 교수 피드백을 반영해 여러 학교 정보 출처를 통합 탐색하는 구조로 확장

6개 출처 통합 자체를 실제 사용자 조사로 검증된 사실처럼 표현하지 않는다.

### 주요 기능

현재 실제 구현된 F1~F9를 기준으로 작성한다.

- 통합 목록
- 출처 배지
- 키워드 AND 검색
- 출처 필터
- 기간 필터
- 조건 칩 및 초기화
- 상세 화면
- 탐색 상태 유지
- 결과 없음 복구
- 잘못된 상세 ID 복구
- 샘플 데이터 고지
- 기본 접근성

구현되지 않은 기능은 구현된 것처럼 쓰지 않는다.

### 대표 사용자 과업

## 2. PROMPTS.md 점검

이번 과제 제출물에는 개발 과정에서 사용한 프롬프트 전체가 필요하다.

기존 `PROMPTS.md`를 점검한다.

원칙:
- 프롬프트 원문을 요약하거나 다시 쓰지 않는다.
- 실제 입력한 내용 그대로 유지한다.
- P01·P02가 claude.ai에서 수행됐다는 기록을 숨기지 않는다.
- P03 이후 Claude Code에서 실제로 입력한 프롬프트는 raw-log를 기준으로 확인한다.
- 존재하지 않는 프롬프트를 만들어 넣지 않는다.

각 항목은 가능하면 다음 정도의 메타정보를 포함한다.

- 번호
- 단계
- 도구
- 목적
- 프롬프트 원문
- 결과 요약

하지만 원문 자체는 수정하지 않는다.

## 3. raw-log 점검

`prompts/raw-log.md`에 P03 이후 프롬프트가 실제로 기록돼 있는지 확인한다.

누락된 항목이 있다면 자동으로 내용을 지어내지 않는다.

누락 사실만 알려준다.

raw-log 자체의 기존 기록은 수정하거나 정리하지 않는다.

## 5. 스크린샷 준비

`docs/screenshots/` 폴더에 제출용 스크린샷을 넣을 수 있도록 정리한다.

Claude Code가 실제 브라우저 화면 캡처를 할 수 없다면 빈 이미지 파일을 만들지 말고, 사용자가 직접 캡처해야 할 화면 목록만 문서로 정리한다.

추천 화면:

1. 기본 통합 목록
2. `졸업요건` 검색 결과
3. 출처+기간 필터 적용 화면
4. 상세 화면
5. 결과 없음 + 복구 화면

필요하면 `docs/screenshots/README.md`를 만들어 각 파일명과 캡처 조건을 안내한다.

예:
- `01-main.png`
- `02-search.png`
- `03-filter.png`
- `04-detail.png`
- `05-empty-recovery.png`

이미지가 없는데 있는 것처럼 README에 링크하지 않는다.

## 7. Git 상태 점검

Git 저장소가 아직 초기화되지 않았다면 임의로 원격 저장소를 만들거나 push하지 않는다.

대신 사용자가 실행할 명령과 순서를 알려준다.

이미 Git 저장소라면 변경 파일 상태만 알려준다.

사용자 허락 없이:
- GitHub 저장소 생성
- 원격 push
- GitHub Pages 설정
은 하지 않는다.
