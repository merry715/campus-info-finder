# 캠퍼스 정보 통합 탐색 HCI 프로토타입

대학 내 여러 게시판과 정보 출처에 흩어진 공지를 한 화면에서 탐색할 수 있도록 설계한 HCI 프로토타입으로, 국립목포대학교 공개 게시글을 기반으로 구성했습니다.

- **배포 사이트**: [https://merry715.github.io/campus-info-finder/](https://merry715.github.io/campus-info-finder/)
- **GitHub 저장소**: [https://github.com/merry715/campus-info-finder](https://github.com/merry715/campus-info-finder)
- **Claude Code 프롬프트 기록**: [PROMPTS.md](PROMPTS.md)
- **수업**: 휴먼컴퓨터인터페이스 (2026-2), 개인 프로젝트

---

## 1. 프로젝트 배경

### 문제를 발견한 곳

국립목포대학교 홈페이지 공지사항에서 과거에 봤던 공지를 다시 찾으려는 과정의 불편함에서 출발했습니다.

### 실제로 관찰한 범위 [관찰]

맥락질의 참여자 P01(1명, 3학년)이 학사공지와 일반공지 사이를 오가며 공지를 찾는 과정을 관찰했습니다. 게시판 위치를 확신하지 못하면 탐색이 반복되고, 경로가 막히면 처음 화면으로 돌아가는 패턴이 나타났습니다. 관찰 범위는 홈페이지 공지사항 내부 2개 분류이며, 참여자 1명이므로 일반화할 수 없습니다.

### 확장한 설계 방향 [가설]

교수님 피드백을 반영해, 학교 정보가 여러 출처에 흩어져 있을 때도 한 화면에서 찾을 수 있는 구조로 설계를 확장했습니다. **여러 출처를 통합하는 구조는 사용자 연구로 검증된 사실이 아니라 설계 가설(H1)입니다.** 이 프로토타입은 그 가설을 실제 MNU 데이터 환경에서 시험해 보기 위한 것입니다.

## 2. 사용자 연구에서 발견한 문제와 구현 방향

| 사용자 연구에서 발견한 문제 | 구현 방향 |
|---|---|
| 게시판 위치를 기억해 직접 탐색, 예상 위치에서 찾지 못하면 다른 게시판으로 이동 | 여러 원본 출처를 한 목록에 통합, 출처를 먼저 고르지 않아도 탐색 가능 |
| 분류 간 직접 이동 경로 없음 — 첫 화면으로 돌아가야 함 | 같은 화면에서 출처·기간 필터 전환 |
| 정확한 제목을 기억하지 못함 | 제목·내용·작성자 AND 검색 + 제목 자동완성 |
| 기간을 대략적인 월로만 기억함 | 최근 1개월·3개월·1년·직접 설정 기간 필터 |
| 같은 공지가 여러 게시판에 존재할 수 있음 | 중복 게시글 통합(1개 카드) + 여러 원본 출처 보존 |
| 고정 게시글이 일반 게시글 탐색 공간을 반복 차지 | 고정 게시글을 별도 패널로 분리 |
| 검색보다 목록 탐색을 선호하는 사용자도 있음 | 검색 없이도 목록만으로 탐색 가능하도록 설계 |

**근거 기호**
- M: 맥락질의 세부 관찰 메모 번호
- E: 기존 인터페이스 평가 항목 번호
- H: 설계 가설 번호

**설계 가설**

| ID | 가설 | 출발점 |
|---|---|---|
| H1 | 학교 정보는 여러 출처에 흩어질 수 있고, 사용자는 이를 오가며 찾는다 | 교수 피드백 |
| H2 | 출처를 먼저 고르지 않는 통합 탐색은 출처 간 이동 횟수와 완료 시간을 줄인다 | P01 관찰을 확장 |
| H3 | 결과마다 출처 배지와 게시일이 있으면 상세를 열기 전에 판단할 수 있다 | 06 R2 |
| H4 | 출처·기간 필터를 같은 화면에서 바꿀 수 있으면 첫 화면으로 돌아가는 일이 사라진다 | 06 R3 |
| H5 | 키워드 검색은 정확한 제목을 몰라도 결과를 좁히는 데 도움이 된다 | 01 연구자 경험. **P01은 검색을 쓰지 않은 반대 사례** |
| H6 | 상세에서 돌아올 때 조건이 유지되면 같은 조건을 다시 입력하지 않아도 된다 | 06 To-be 5단계 |

## 3. 주요 기능

### 통합 목록

- 출처를 고르지 않아도 모든 항목을 최신순으로 표시 (기본 화면)
- 한 화면에서 출처·주제·기간 필터를 조합해 결과를 좁힘
- 필터·검색어·페이지를 URL 해시에 저장 — 뒤로 가기·새로고침 후에도 상태 유지
- 조건을 변경하면 1페이지로 자동 이동

### 통합 검색

- 제목·내용·작성자·작성기관 대상 AND 검색 (여러 단어 모두 포함)
- 대소문자·앞뒤 공백 무시
- 제목 기반 자동완성 (일부 입력 시 후보 표시)

### 필터

- **주제**: 학사·수업 / 장학·등록 / 취업·진로 / 입학 / 비교과·대외활동 / 대학생활·지원 / 학교·기관소식
- **원본 출처**: 일반공지 / 학사공지 / 장학 / 취업 / 의과대학소식
- **기간**: 전체 / 최근 1개월 / 최근 3개월 / 최근 1년 / 직접 설정
- 적용 중인 조건은 조건 칩으로 표시, 개별 해제 가능
- 결과 0건일 때 조건 해제·전체 출처 재검색·전체 초기화 복구 버튼 제공

> 주제는 탐색 편의를 위해 프로토타입에서 재분류한 값입니다. 원본 출처는 실제 게시 위치(게시판)입니다.

### 정렬 및 탐색

- 최신순 / 오래된 순 / 제목순
- 월별 그룹 구분자 (모든 정렬 방식에 적용)
- 10개 단위 페이지 번호 그룹 (1~10, 11~20, …)
- 이전/다음, 10페이지 이동, 직접 페이지 번호 입력
- 총 N건 · N페이지 표시

### 보기 방식

- 1열 / 2열 / 3열 전환 (SVG 아이콘 버튼, 접근성 label 포함)

### 중복 게시글 통합

동일 공지가 여러 원본 게시판에 게시되면 하나의 카드로 통합하고, 모든 원본 출처를 카드 안에 함께 표시합니다.

```
통합 게시글 카드
 ├─ 주제: 비교과·대외활동
 └─ 원본 출처
     ├─ 일반공지 (일반 게시글)
     └─ 학사공지 (고정 게시글)
```

원본 게시 위치와 고정 여부는 출처별로 개별 보존됩니다.

### 고정 게시글 패널

원본 게시판에서 고정된 게시글을 오른쪽 별도 패널에 표시합니다.
- 고정 여부는 출처별로 관리 (`sourceEntries[].isPinned`)
- 접기/펼치기 가능 (접근성 aria-expanded 처리 포함)
- 검색 결과가 고정 게시글에만 있을 때 중앙 영역에 안내 문구 표시

### 상세 화면

- 제목, 원본 출처, 주제, 작성자, 작성일, 내용, 첨부파일 안내
- 여러 원본 출처가 있으면 출처별 원문 링크 각각 제공
- "검색 결과로 돌아가기" — 기존 검색 조건·페이지 복원

### 접근성 (F9)

- 본문 건너뛰기 링크
- 모든 입력 요소에 가시적 `<label>`
- 출처 체크박스, 기간 라디오에 `<fieldset>` + `<legend>`
- 키보드(Tab/Shift+Tab/Enter/Space)만으로 대표 과업 수행 가능
- `:focus-visible` 포커스 표시 유지 (outline 제거 금지)
- 화면 전환(목록 ↔ 상세) 시 포커스를 새 화면 제목으로 이동
- 결과 건수 변경 시 `aria-live="polite"` 로 보조기기 알림
- 고정 게시글 접기/펼치기에 `aria-expanded`, `aria-controls`
- 출처를 색만으로 구분하지 않음 — 배지에 항상 텍스트 라벨
- `prefers-reduced-motion` 존중

## 5. 대표 사용자 과업

| 과업 | 근거 | 흐름 |
|---|---|---|
| T1. 출처를 모르는 정보 다시 찾기 | P01 재현 | 기본 목록 → 키워드 검색 → 여러 출처 결과가 섞여 표시 → 원본 출처 배지와 날짜로 구분 → 상세 → 돌아가기 |

| T3. 결과 없음에서 복구하기 | F7 | 검색어 + 맞지 않는 출처 → 0건 → [전체 출처에서 다시 찾기] → 결과 발견 → 상세 |

T4의 스크롤·포커스 복원은 후순위입니다. 현재 페이지와 조건이 유지되면 통과로 봅니다.

## 6. 기술 스택

HTML, CSS, 순수 JavaScript ES Modules만 사용합니다. 외부 프레임워크, 빌드 도구, npm 패키지, CDN을 사용하지 않습니다.

| 항목 | 선택 이유 |
|---|---|
| HTML + CSS + Vanilla JS | 외부 의존 없이 GitHub Pages에서 그대로 배포 가능 |
| ES Modules | 파일 목적별 분리, 빌드 없이 브라우저에서 직접 동작 |
| 해시 라우팅 (`#/`, `#/item/{id}`) | GitHub Pages 새로고침 시 404 방지 |
| `node --test` | 외부 라이브러리 없이 순수 함수 단위 테스트 |
| 고정 스냅샷 기준일 (`2026-11-11`) | `new Date()` 사용 시 시간이 지나 필터 결과가 비어지는 문제 방지 |

## 9. Claude Code 활용 과정

이 프로젝트는 P01부터 P20까지 총 20단계에 걸쳐 Claude Code를 활용해 구현했습니다. 매 단계는 이전 구현 결과를 브라우저에서 직접 확인한 뒤, 발견한 문제와 새로운 요구사항을 다음 프롬프트에 반영하는 방식으로 진행했습니다.

| 단계 | 주요 작업 |
|---|---|
| P01–P02 | 프로젝트 뼈대, CLAUDE.md 규칙 정의, 초기 샘플 데이터 |
| P03–P05 | 통합 목록·출처 배지·검색·필터·상세 화면·URL 상태 유지 |
| P06–P09 | 결과 없음 복구, 접근성 점검, 테스트 작성, UI 완성도 개선 |
| P10 | README 및 PROMPTS.md 초기 정리, 배포 준비 |
| P11–P13 | 정렬·열 보기·직접 기간 설정·10페이지 이동, 월별 그룹, 서비스 아이덴티티 |
