# 캠퍼스 정보 통합 탐색 (HCI 프로토타입)

재학생이 필요한 학교 정보의 정확한 제목이나 위치를 몰라도 여러 정보 출처의 샘플 데이터를 한곳에서 탐색할 수 있도록 만든 HCI 웹 프로토타입입니다.

> **샘플 데이터 안내**
> 이 프로젝트의 모든 게시물, 출처, 부서, 첨부 파일은 2026-2학기 휴먼컴퓨터인터페이스 수업 과제를 위해 만든 샘플 데이터입니다.
> 실제 학교 시스템과 연결되어 있지 않으며, 실제 공지 내용이 아닙니다.

## 1. 프로젝트 배경

### 문제를 발견한 곳

국립목포대학교 홈페이지 공지사항에서 필요한 공지를 다시 찾는 과정의 불편함에서 출발했습니다.

### 실제로 관찰한 범위 [관찰]

맥락질의 참여자 P01(1명, 3학년)이 홈페이지 안에서 학사공지와 일반공지 사이를 오가며 공지를 찾는 과정을 관찰했습니다. 게시판 위치를 확신하지 못하면 탐색이 반복되고, 경로가 막히면 처음 화면으로 되돌아가는 패턴이 나타났습니다. 관찰 범위는 홈페이지 공지사항 내부의 2개 분류뿐이며, 참여자가 1명이므로 일반화할 수 없습니다.

### 확장한 설계 방향 [가설]

교수님 피드백을 반영해, 학교 정보가 여러 출처에 흩어져 있을 때도 한곳에서 찾을 수 있는 구조로 설계를 확장했습니다. **6개 출처를 통합하는 구조는 사용자 연구로 검증된 사실이 아니라 설계 가설(H1)입니다.** 이 프로토타입은 그 구조를 샘플 데이터로 시험해 보기 위한 것입니다.

## 6. 기술 스택

HTML, CSS, 순수 JavaScript ES Modules만 사용합니다. 외부 프레임워크, 빌드 도구, npm 패키지, CDN을 사용하지 않습니다.

| 항목 | 선택 이유 |
|---|---|
| HTML + CSS + Vanilla JS | 외부 의존 없이 GitHub Pages에서 그대로 배포 가능. 실습 과제로 기술 구조를 명확하게 파악하기 위함 |
| ES Modules | 파일을 목적별로 분리하면서도 빌드 없이 브라우저에서 직접 동작 |
| 해시 라우팅 (`#/`, `#/item/{id}`) | GitHub Pages에서 새로고침 시 404가 발생하지 않음 |
| `node --test` | 외부 라이브러리 없이 순수 함수 단위 테스트 가능 |
| 고정 샘플 기준일 (`2026-11-10`) | `new Date()`를 쓰면 시간이 지나 필터 결과가 비어버리는 문제 방지 |

## 8. 접근성 구현 항목 (F9)

P07에서 전체 점검하고 P09에서 유지 확인한 항목입니다.

- 키보드(Tab/Shift+Tab/Enter/Space)만으로 T1~T4 대표 과업 전체 수행 가능
- 모든 조작 요소에서 `:focus-visible` 포커스 표시
- 화면 전환(목록 ↔ 상세) 시 새 화면의 주 제목으로 포커스 이동
- 검색 입력에 보이는 `<label>`
- 출처 체크박스와 기간 라디오에 `<fieldset>` + `<legend>`
- 결과 건수 변경 시 `aria-live="polite"` 로 보조기기 알림
- heading 구조: 목록 h1 → 카드 제목 h2 / 상세 게시물 제목 h1
- 출처를 색만으로 구분하지 않음 — 배지에 항상 텍스트 라벨
- 본문 텍스트 명도 대비 4.5:1 이상 목표

Lighthouse Accessibility 점수는 직접 측정하지 않았습니다. 브라우저 DevTools에서 직접 확인하세요.

- 실제 학교 시스템으로 일반화할 수 없음
